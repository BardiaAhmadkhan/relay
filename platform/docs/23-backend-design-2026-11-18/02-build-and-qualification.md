# Relay | Build and qualification plan

**18 November 2026 · Handoff to the next builder.** The comparator is the working-tree v3.1 service profiled in the [design](01-engine-design.md). The work below is proposed. Start by preserving the exact reference, then build one complete rider-to-shop workflow before enabling any new automatic decision.

## 1. Order of work

| Order | Deliverable | Definition of done |
| --- | --- | --- |
| 0 | Reference and reuse record | Byte and profile checks pass, including projector. Protected images and untouched item groups are inventoried. |
| 1 | Cloud-hosted reference | Real readiness, matching artifacts, measured decision parity, bounded queue and compute billing. |
| 2 | Two native phones connected to that reference | Each package ships zero weight bytes. Each captures, resumes and delivers a real case and handles a reported exclusion without inference. |
| 3 | Durable evidence and shop verdict | A stale result cannot change a newer draft. Retries are idempotent. Confirmed protective-area findings block across both rider policy and reviewer UI. |
| 4 | Item ownership and linked close-up | Rider and shop can connect the relevant area to the second observation, decline an unhelpful request, and reach a documented disposition. |
| 5 | Qualified image and compute optimizations | Fresh paired field evidence improves the preregistered objective at the agreed risk and coverage within the size cap. |
| 6 | Optional same-size model candidate | Independent decision to promote. The original model stays reproducible. |

Use existing TypeScript, Fastify, Zod, Sharp and Expo/React Native. Python is appropriate for offline statistics and labeling tools. Restrict native Swift/Kotlin to platform capabilities that Expo cannot deliver reliably. Keep worker/scorer contracts language-independent. An optional C++ inference optimization must prove that it preserves outputs. A separate queue product, new frontend framework or distributed inference fleet would add integration work before this workload requires it.

## 2. Reference and hosted inference

1. **Freeze.** Check the 66-file reference in `measurements.json`. Record working-tree contents and actual artifacts. Committing only the old Git revision would lose the implemented engine. Collect rights, provenance and intended use for each dataset. The owner's private regression photos remain local. Select a cloud-permitted parity pack. Preserve a separate prospective qualification set.
2. **Pin.** From `server/index-v2.ts`, `packages/vision/v2/{plan,scorer-local,scorer-chain,battery}.ts`, the two threshold files and `scripts/local-vision.mjs`, build a locked Linux container using the same runner and GGUF blobs. Check sizes and hashes at build and startup. Record template, question order, token normalization/coverage, colour/orientation, 1600/512 image processing, driver and device. Start with plan and cascade enabled, prompt-cache RAM disabled and reference recycling interval 25. Test actual Linux behavior after each recycle.
3. **Deploy the minimum unit when authorized.** A TLS API and private GPU runtime can initially share a worker. Place job/assessment records and consented photos outside the worker’s lifetime. Restrict runtime access to the API. Keep the v2 wire contract for existing clients, a shop-scoped session for the cloud app and a separate reviewer role. Preserve image/pixel/time limits before inference. The first binary upload path can coexist with v2 base64 for compatibility.
4. **Make readiness real.** The current default warmup returns zero inner calls. Separate liveness, readiness and degraded states. Load the exact artifacts, then send an image and a question the enabled plan executes. Bypass the result cache. Require a valid answer, positive evaluated tokens and the matching profile. Drain active jobs before recycle and run the same real probe before accepting another job. Guard against false-ready workers and failed probes. Record cold duration separately.
5. **Control demand.** Begin with one inference lane per GPU, bounded queue, assessment-aware fairness, retry hints and a per-item compute budget. Start work only if consent and revision still match. Timeouts/rate limits lead to retryable or human-review states. Pin one worker warm during the judged window. Measure 1/2/4 simultaneous intakes, canceled requests, lease recovery, cold and warm operation before adding replicas. A second copy of the same model is an operating cost.
6. **Measure parity.** Compare Linux cloud against local v3.1 on identical permitted bytes. Test fresh load, repeated inferences, ABC/CBA order, after recycle and across replica restarts. Compare raw scores, allowed-token mass, signed observations and policy actions. Publish all near-threshold reversals. Treat unstable cases as review while qualifying that profile. The current local cost meter reports a token rate of zero. Collect provider worker-seconds, memory time, upload bytes, starts and idle separately.
7. **Evidence of success.** A real phone HTTPS trace, package hash, host profile, worker logs showing an actual completed inference at readiness, cost ledger and matched decision records. An HTTP 200, web screenshot or successful model-tag query alone is insufficient.

## 3. Both mobile clients and the specialist handoff

1. Replace the cloud profile’s `app/src/api.android.ts` selection and shared `useRelay.ts` engine negotiation with one explicit cloud client. Scope the native offline plugin, weight assets and `llama.rn` out of that build. Allow Internet in the Android cloud manifest. Set a configured HTTPS destination and reject incompatible health profiles with a recoverable message. Do not silently change provider or switch to v1. Preserve the existing offline artifact for historical comparison. The iOS and Android clients use the same business policy.
2. In `app/src/session.ts`, retain source detail in private storage when capture rights and device capacity allow. The baseline downsizes to 1600 px and saves JPEG at 0.82. Generate normalized overview, screen preview and an on-demand native-pixel region from an oriented parent. Strip metadata from uploads, cap decoded pixels/memory and purge local intermediate files with the draft. If the original is unavailable, ask for a new close-up. Test HEIC import, rotation, JPEG, low-memory devices, interrupted photo-library downloads, denied permission and unavailable camera.
3. Persist draft/revision, file generations, pending operation IDs, photo SHA, upload receipt and consent. Store session secrets in the OS secure store. Detect app relaunch and reconnect. Avoid duplicate uploads and model calls. When connectivity is lost, display pending and preserve the next native capture. Reported exclusions still take effect. Stop unnecessary pending work after withdrawal or exclusion.
4. In `app/src/useRelay.ts`, `api-v2.ts` and the session model, bind score reuse to assessment, photo generation, destination and engine profile. Attaching an obsolete result may complete a historical job. It must never update the current result. Make mandatory view acquisition separate from an optional diagnostic request. Repeated “review” taps and app restarts do not consume attempts.
5. Reuse `app/src/brief-v2.ts`, `result-v2.tsx` and the existing optional `server/review-v2.ts` workflow. A “Send to specialist” action must submit the consented record and return a visible receipt. Local sharing remains a different action. Show source overview, paired detail, side/zone, explicit unknowns and the question that needs settling. Have the reviewer enter observation/zone before model cues when collecting independent labels.
6. Save an outcome linked to the reviewed revision. Require structured “in protective area / outside / unresolved” and the source of established history. A confirmed crash or protective-area exclusion cannot be bypassed by a grade or free-text note. Historical reported positives are preserved through corrections. If history or a relevant zone remains unresolved, route to in-hand inspection rather than issuing an offer. Permit the shop to record an eligible item’s commercial disposition.
7. Inspect both native build artifacts and first-launch traffic for zero model files or downloads. Perform each of capture, background/foreground, lost network, edited disclosure, wrong boot, duplicate button press, retake, cloud consent decline, specialist submission and verdict receipt on one physical iPhone and one physical Android. Record OS, build ID, handset and trace. Browser and emulator evidence have their own rows.

## 4. State and contracts for the builder

Extend Fastify with a versioned assessment resource and additive migrations. Use PostgreSQL with a job table as the initial durable store, plus private encrypted blob storage. The table names below describe contracts. One database transaction owns each state transition and its queued work.

| Entity | Required fields | Mutation rule |
| --- | --- | --- |
| Assessment | shop scope, assessment ID, revision, consent/destination, shop policy ID, stage | Compare-and-swap revision. One current decision per revision. Closed/deleted states reject obsolete work. |
| Disclosure | event ID, assessment, question, answer, source, event/recorded times | Append. Retain earlier positives and reconciliation evidence. |
| Photo/rendition | generation, assessment, item, intended role/side, hash, pixel size, oriented-parent transform, quality and consent | Replacement creates a generation. Store reversible crop coordinates and whichever parent was actually available. |
| Observation | ID, photo-generation/region, type, answer state, source, raw token mass/score, mapped band, profile, time | Immutable. Distinguish model, rider and in-hand observation. Link conflicting evidence explicitly. |
| Finding | item/side, concern, proposed area and certainty, supporting observation IDs, status, authority and disposition | Open → detail requested/person required → established exclusion or explicitly resolved suspicion. Retiring a photo cannot erase a finding. |
| Capture request | stable request ID, finding, revision, requested view/side, intended question, issued/accepted/declined status | Redisplay and retry reuse the request ID. Count an extra attempt once when accepted evidence or explicit decline is received. |
| Job/receipt | idempotency key, input/rendition hash, job type, consent, profile, lease, attempt, status, billable work | Lease expiry permits retry. Compare worker token/revision before accepting completion. Deduplicate logical results. |
| Verdict | reviewed revision, prior decision ID, reviewer, structured facts, qualifying mode, evidence IDs, outcome, time | Idempotent save. Concurrent conflicts require reconciliation. Established exclusions dominate every commercial path. |

**Proposed API.** `POST /v3/assessments` creates a scoped session. `POST /v3/assessments/{id}/photos` issues a bounded upload handle. Commit verified bytes and enqueue scoring atomically after upload. `POST /v3/assessments/{id}/events` takes expected revision, client operation ID and one disclosure/replace/consent/request-response event. `GET /v3/assessments/{id}` returns canonical revision, job state, open findings, next action and decision. Start with polling plus backoff. `POST /v3/assessments/{id}/reviews` returns a durable handoff ID. Staff attach a verdict to the revision they inspected.

**Concurrency and recovery.** Same operation ID and content returns the previous response. A changed payload with the same ID is a conflict. If two devices edit revision 4, at most one becomes revision 5. The second sees the fresh snapshot. A late upload cannot attach to a replacement photo. Retry after a lost acknowledgment must not create a second logical job. A remote call that finishes just before a worker crash can still incur duplicate physical compute. Meter and cap that. Cache only identical governed inputs. Keep cache entries scoped, bounded and expirable.

**Migration and privacy.** Keep v2 scores as historical if missing binding fields. Revalidate or rescore with consent. Pin shop rules separately from inference, record key ID/rotation on signed receipts, and scope review media to authorized staff. Proposed pilot defaults are 24 hours for unsubmitted cloud evidence and a separately agreed review-retention period. Delete originals, renditions and derived caches on expiry or deletion, stop pending jobs, and retain only permitted non-image audit fields. Re-check backup and vendor retention before promising deletion deadlines. Rollback is a profile change. It must preserve drafts and previously established stops.

## 5. Experiment sequence

Each experiment has a frozen comparator, an intended benefit and a condition for retiring it. Run the reference on the same physical items throughout. Introduce one change per comparison.

| Candidate vs current reference | Design and measure | Guard and action |
| --- | --- | --- |
| Item and matching-pair attribution | Photograph the same gear alone, on hanger/mannequin, near torn bystander clothing, as a matching pair and beside a second pair. Use one closed scene/ownership question when it could change disposition. Score incorrect terminal exclusions and additional staff time. | No admission of grounded possible exclusions to an offer. Preserve separation of eligible pairs from scenes. Global relaxation of the single-item threshold admits scenes. |
| One linked physical close-up vs current generic request | Record real overview, targeted view and a genuinely unrelated or unhelpful view. Randomize request phrasing across riders and blind staff to treatment. Measure successful resolution, completion, reviewer seconds and incorrect reversals. | An unrelated detail resolves zero holds. No reported/expert-confirmed exclusion can reopen. If a second photo only adds work, offer immediate handoff. |
| Bounded crop plus overview vs whole image | Predeclare center crop, a rider tap and systematic coverage as separate arms. A crop uses native pixels and an explicit transform. Preserve the full frame. Include normally low-scoring overviews. Count recovered consequential misses per additional GPU-second and false holds per item. | Maximum two extra crop evaluations per item in the pilot. Include prints, seams, black leather, reflections and damage near mask boundaries. No quiet crop proves unobserved surfaces clear. |
| Capture guidance vs fixed focus gate | Compare baseline global focus with localized sharpness/subject occupancy on true directional motion, glare and dark fabric with sharp backgrounds. Include both phones and genuinely readable low-texture gear. Measure unnecessary prompts and failure to flag expert-unreadable views. | Do not change a global gate based on generated blur alone. Accessibility or missing camera support must preserve a manual fallback. |
| Cheaper preparation/inference vs identical cloud reference | Decode once and derive comparable scales. Coalesce consent-compatible jobs. Benchmark 1/2/4 concurrent intakes, CPU/RSS, GPU seconds, cold/warm p95, numerical equivalence and branch agreement. | Pin encoder, resampling and prompt order. E5 found little repeated-image saving on this runtime. A reusable vision embedding per rendition is a separate experiment. Require equivalence, bounded memory and isolation between assessments. |
| Label facts vs label legibility alone | Use the existing cloud model for transcription only if a specific label fact helps staff. Evaluate character/field errors, missing/unreadable outcomes and rider correction on real multilingual, creased and worn tags. | Label text is provenance for identification, never individual performance or authenticity. Any independent learned OCR engine must fit in the aggregate cap by displacing other weights. |
| Size-neutral quantization vs pinned GGUF | Choose one tensor-precision allocation or smaller replacement before looking at qualification examples. Rebuild from the licensed input as appropriate. Hash/count all components. Compare conditional score drift, token coverage, grouping, VRAM, speed and field outcomes. | No deployment for bytes saved alone. Reject larger learned footprint, training, uncompensated safety regression or failure to improve the named cost/quality objective. No weight modification is necessary for the day-of design. |

**First replay before any cost claim.** On 346 historical overviews, the existing one-item score was present on 335. Of 282 low scores, 281 already led to retake. Their full-service time had a 4,004.5 ms median, which includes work that still has to be done. Only one of seven damaged overviews had this score because the current plan often exits earlier. Measure the new scene check on a representative consecutive series and all damage positives in shadow. Never credit the whole historical duration as savings. [Replay](03-evidence.md)

**Example of a linked request.** A rider and worker can reconstruct this proposed object without interpreting free text. The box below is illustrative, not a measured localization.

```json
{
  "requestId": "req-17",
  "assessmentRevision": 4,
  "findingId": "mark-2",
  "parentPhoto": { "id": "front-1", "generation": 1 },
  "itemSide": "left",
  "region": { "space": "oriented_parent_0_1", "xyxy": [0.21, 0.53, 0.42, 0.76] },
  "regionSource": "rider_pointed",
  "purpose": "distinguish_surface_scuff_from_material_break",
  "expectedResponse": "fresh_detail_or_decline",
  "status": "issued"
}
```

In the database the request also carries shop, item ID and engine/policy version. A response names the request, parent generation and physical side and carries its own capture ID. A crop of the original carries a rendition ID and cannot be mistaken for a fresh capture. A reader that does not recognize the version preserves the draft and requests a compatible assessment.

**Decision table for the first new planner.** Positive history → stop before scoring. Missing basic view → keep all accepted views and request the missing one. Root subject unclear with a visual hit → hold and request a clean overview or send to staff. Established target with potentially informative mark → request one specifically linked detail, unless already answered or declined. Suspect mark without a stable location → staff or rider-assisted location, with uncertainty recorded. Strong evidence of exclusion → withhold pending authority or exclude under established shop facts. Complete qualifying case → shop consideration or signed commercial decision. Precedence must be tested across multiple simultaneous facts. Keep every earlier positive observation in the reviewer brief.

**Optional compute optimization.** If profiling shows repeated vision encoding dominates, test reusable image embeddings keyed to image, transform, projector and runtime. Keep language state and question-specific probabilities isolated. A single free-text response for all questions is a different classifier with different calibration. Check byte/tensor mapping, distributions, costs and decision parity before even shadow rollout. [llama.cpp multimodal interface](https://github.com/ggml-org/llama.cpp/blob/master/tools/mtmd/mtmd.h)

### First candidate configuration

Keep the reference scoring and calibration available under their original profile ID. Create a new experimental profile in which visual holds are open observations, rider-attributed positions are provisional, and only an in-hand specialist can resolve a consequential suspicion or finalize an eligible commercial result. Inference may take a case off the automatic-offer path immediately. It cannot supply a missing history or change an established exclusion.

| Switch in the first candidate | Proposed setting and decision boundary |
| --- | --- |
| Size and model | Exact baseline manifest. One shared multimodal model on the cloud worker. Zero mobile learned components. |
| Required views | Existing front/back/label for supported items until the signed shop matrix says otherwise. Missing or inaccessible label routes to staff with the reason; ordinary repeated submissions use the same action ID. |
| Confirmed history | Stop before any new model work. Preserve all affirmative disclosures even if the owner later changes an answer. |
| Subject attribution | Use the existing cheap category/one-item checks as observed features. Evaluate the new multi-class pair/context question in shadow first, with independently labeled one pair, two pairs, scene and single item. It never authorizes eligibility on its own. |
| Region selection | Start with a rider- or expert-pointed rectangle and one wider parent image. Persist oriented normalized coordinates with an explicit source. A different angle is new evidence only when tied to the same finding and physical side. Unknown location goes to staff or a voluntary rider tap. |
| Extra compute and rider effort | At most two additional region evaluations and one optional diagnostic photo per item in the pilot. This is a hard maximum, not a quota. Skip when neither action can change the route or assist the reviewer. Guard against excessive *total* visual calls including retries, and expose provider limits. |
| Independent audit | On a consented offline or shadow cohort, take a deterministic 1-in-10 sample of otherwise quiet overviews using a precommitted item-hash salt. Examine the same item with systematic coverage or expert review. Log sampling probability. Do not substitute it for full evaluation on known damaged and repaired gear. |
| Automatic reconsideration | Off until a specifically scoped candidate has its own independent resolution labels and qualification result. Retire isolated photo hypotheses only through structured adjudication. A grade never overrides a hold. |

**Translating an area into an inspectable crop.** Treat the proposed rectangle as unit coordinates in the orientation-corrected parent. Reject zero-area or out-of-parent geometry. For the initial experiment, expand each edge by 15% of the rectangle's corresponding side and clamp to the parent, store both boxes and crop the source once. Draw the original rectangle on the overview and show the exact patch used. A low-resolution source or one cropped too tightly to include context prompts a physical close-up or a person. Compare 0% and 15% padding on development only. The 15% margin and 1-in-10 sampling rate are explicit trial settings, not measured optima.

**What to log in every experiment.** Protocol ID, baseline/candidate profiles, split and sampling rules, item-family and capture IDs, labels and rater/authority, revision/view, raw and remapped scores with token mass, question/compute path, outcome and next action, exception/timeout, GPU and staff timing, consented read permission, actual bytes, license and retention. Retain the reason for each differing case and publish all predeclared metrics and missing rows. Keep geographic and personal metadata separate from inference logs.

## 6. Cloud economics and capacity

Benchmark **Modal L4** first as a self-controlled endpoint hosting the pinned image. It exposes GPU/CPU/memory prices and warm-container configuration. Compare an identically packaged Runpod Flex or Active worker if region, terms, parity, cold latency or the actual invoice favors it. As a sensitivity example, 30 staff seconds at an assumed $30/hour costs $0.25 per review. A more expensive image request can save money if it makes that review shorter. Measure the difference before enabling it.

## 7. Qualification against real-world use

**Unit and ground truth.** One physical item or pair with all photos, transformed derivatives, close-ups, repeated submissions, phones and verdicts. Group by item, source family, photographer, capture site/session and shared crash where known. Audit duplicate candidates manually. A low-perceptual-distance heuristic cannot certify independent viewpoints. Two qualified observers independently record motorcycle-specific identity, visible damage/repair, region, protective-area relevance, uncertainty and next action. Record rider disclosure and known history separately. First label photos, then the in-hand inspection when available, and preserve disagreements. Keep model output hidden until independent entry. An adjudicator settles disagreements or records indeterminate.

**Acquisition.** Gather prospective intakes at two independent settings with both phone families. Include ordinary wear, real confirmed exclusions, known protective-area repairs, factory reinforcements, fashion lookalikes, unpaired boots/gloves, missing tags, unknown histories and unjudgeable images. Obtain real cases from the shop, with rights. Never damage protective gear to make a test. Enrich a sensitivity set for rare exclusions and separately sample consecutive real intakes for coverage, abandonment, referral and prevalence. Report refusals and incomplete cases. Do not invent negatives for missing history. Identify the role of organizer photos before opening them.

**Splits and drift.** Treat E1–E19 and this handoff’s purposive examples as development for future redesign. Separate development, calibration and *one* locked candidate-vs-reference qualification at item-family level. Follow with a new prospective site or day. Record policy, model/runner, firmware, image-processing/threshold hashes, capture conditions, result latency, exception and decision. If a change follows an exposed test failure, add it to permanent regression tests and get fresh qualification data. Stage unlabeled drift monitoring by category, source, view, feedback/abandonment, thresholds-nearby proportion and human disagreement. A drift alert increases review or initiates an authorized new study. It never automatically retrains or relaxes policy. [WILDS](https://proceedings.mlr.press/v139/koh21a.html) · [Learn then Test](https://arxiv.org/abs/2110.01052)

| Primary measure | Denominator and comparisons | Proposed promotion decision |
| --- | --- | --- |
| Unsafe recommendation | Confirmed excluded physical items receiving a recommendation / all confirmed excluded items. Also count excluded items / all recommended items. Show raw numerators and denominators. | Any observed unsafe recommendation stops the affected automatic path. All deterministic safety invariants must pass. Show the remaining statistical upper bound. |
| Wrongful terminal exclusion | Commercially eligible items wrongly excluded / all such eligible items in the cohort. Break out ordinary wear and pairs. | Seek paired decrease at matched risk. Reject a switch that only displaces the workload to universal review. |
| Coverage and selective risk | Automation share of consecutive intakes, errors among automated items, review, abandonment, unknown and incomplete. | Compare at matched safety risk and matched coverage. Include expert-only and always-review controls. |
| Detail value | Actionable resolutions and expert seconds per all prompted items, including declined, irrelevant and unanswered requests. | Compare intent-to-treat and per-completed-photo results. Require correct source linkage, lower work or better observed decisions and no reopening confirmed exclusions. |
| Recognition | Per-item damage and repair sensitivity, false flags, precision–recall, spatial concordance when annotated. Report abstention, severity and per-region counts. | Repair qualifies independently. Generic damage success cannot authorize repair clearance. Preserve uncertainty in sparse phone/category/site slices. |
| Reliability and cost | p50/p95/p99 cold/warm timings, peak RAM/VRAM, billed seconds, retries, duplicate jobs, staff time, all submitted/completed cases. | Proposed targets: p95 warm cloud feedback ≤8 s after accepted upload, p95 decision ≤2 s once all scores exist, zero duplicate logical jobs. Track timeouts in denominators and end-to-end phone timings. |
| Human workflow | First-pass capture, ability to locate a mark, time to meaningful disposition, optional prompts and comprehension. | Formative test with five riders and two staff, counterbalanced order on matched tasks. No population estimate from this small study. |

Pre-register one primary benefit per candidate. A proposed commercial promotion target is ≥15% relative reduction in the selected friction/time/cost outcome with a paired 95% interval favoring improvement, stable safety gates and shop-agreed coverage limits. This is a proposal, not a measured improvement or event rule. Report both discordant counts. Use exact McNemar where appropriate for independent item pairs and item/session-cluster bootstrap intervals for paired differences and timing. Adjust for multiple candidates or use separate locked tests. Avoid presenting visually balanced enrichment as field positive predictive value.

For zero observed failures in **n independent, appropriately sampled** items, the exact one-sided 95% upper bound is `1 − 0.05^(1/n)`. It is 23.84% at 11, 22.09% at 12, 4.95% at 59, 1.99% at 149 and 1.00% rounded at 299. Use exact binomial bounds for nonzero event counts and cluster-aware estimates where necessary. Counts needed to support “risk among recommended items” and “misses among excluded items” use different denominators. With insufficient evidence for automatic recommendations, the pilot still reaches a real yes/hold/no through a qualified person.
